# Верхнеуровневая структура БД

## Описание сущностей
| **Сущность** | **Назначение** |
|----|----| 
| USER	| Пользователи платформы |
| ASSISTANT	| Основная информация об ИИ-ассистентах |
| ASSISTANT_ACCESS	| Права доступа пользователей к ассистентам |
| ASSISTANT_VERSION	| История версий настроек ассистентов |
| CONVERSATION	| Диалоги пользователей с ассистентами |
| MESSAGE | Сообщения внутри диалогов |
| MESSAGE_METADATA	| Дополнительные структурированные метаданные сообщений |


## Важные связи и бизнес-правила
1. **USER — ASSISTANT**

Один пользователь может создать множество ассистентов. У каждого ассистента есть один владелец.

2. **ASSISTANT — ASSISTANT_VERSION**

Один ассистент может иметь множество версий настроек. Каждая версия принадлежит конкретному ассистенту. Комбинация assistant_id + version_number должна быть уникальной.

3. **ASSISTANT — ASSISTANT_ACCESS**

Связующая сущность для реализации отношения многие-ко-многим между пользователями и ассистентами. Она позволяет хранить:
- кому предоставлен доступ;
- к какому ассистенту;
- какую роль имеет пользователь (например, viewer или editor).

4. **CONVERSATION — MESSAGE**

Один диалог содержит множество сообщений. Каждое сообщение принадлежит одному диалогу.

5. **ASSISTANT_VERSION — MESSAGE**

Сообщение должно ссылаться на версию настроек, которая использовалась при его обработке. 

6. **MESSAGE — MESSAGE_METADATA**

У сообщения могут быть дополнительные метаданные. Для их хранения используется JSONB. Примерная структура метаданных может выглядеть так:
```{
  "tool_calls": [
    {
      "tool_name": "search_documents",
      "status": "success"
    }
  ],
  "citations": [
    {
      "document_id": "doc-123",
      "source": "internal_knowledge_base"
    }
  ]
}```
